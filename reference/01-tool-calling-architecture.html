Reference Guide 01

Tool-Calling Architecture & Evaluation Harness

A quick-reference architectural blueprint for the Day 04 Helpdesk AI Assistant.

Topic: AI Agent & Tool Calling Target: Day 04 Lab (VinUni AIA) Associated Code: agent.py, run_eval.py

1. The Agent Tool-Calling Lifecycle

How the Helpdesk Agent interacts with the LLM provider and local tool functions:

Step 1: Context Construction

System Prompt + Messages

User queries or multi-turn transcripts are combined with system_prompt.md and sent alongside tool schemas from tools.yaml.

Step 2: LLM Tool Routing

Completion with Tools

The model outputs either a final direct answer (text) or one or more structured ToolCall(name, args).

Step 3: Tool Dispatch

Local Execution

agent.py looks up TOOL_FUNCTIONS[call.name], executes it safely with **call.args, and packages the result.

Step 4: Evidence Synthesis

AgentRun Packaging

The run produces AgentRun(text, tool_calls, tool_results), enabling audit trails and multi-turn follow-ups.

2. Eval Failure Taxonomy

The evaluation harness (run_eval.py) validates agent behavior against 6 formal failure types:

Failure Type What Happens Root Cause & Fix Location
wrong_tool Model chose check_service_status instead of inspect_device. Ambiguous tool descriptions in tools.yaml. Clarify distinctions and keywords.
wrong_arg_value Model passed service: "outlook" instead of service: "email". Schema missing enum constraints or normalization hints in tools.yaml.
missing_info User said "my laptop is broken" without asset ID; agent guessed or failed instead of calling clarify. Add explicit routing rule in system_prompt.md: when ID is missing, call clarify.
wrong_boundary Model called create_ticket without confirmation, or leaked internal data. Define strict confirmation rules in system_prompt.md (require user confirmation).
unnecessary_tool Model invoked tools for a greeting or simple non-operational question. Instruct model in system_prompt.md to reply directly when no tool is needed.
out_of_scope User asked about weather/sports; agent attempted tool search instead of declining. Define boundary scope in system_prompt.md.

3. Essential Commands Cheat Sheet

# 1. Environment & Preflight
cd starter_v0
python scripts/preflight_provider.py --provider openrouter

# 2. Run Baseline Eval (v0)
python run_eval.py --provider openrouter --version v0 --suite base --eval-cases data/eval_base.json

# 3. Run Adversarial Safety Suite (12 cases)
python run_eval.py --provider openrouter --version v3 --suite adversarial --eval-cases data/eval_adversarial.json

# 4. Run Team-Authored Cases (10 cases: 5 single + 5 multi-turn)
python run_eval.py --provider openrouter --version v3 --suite group --eval-cases data/eval_group.json

# 5. Interactive Chat CLI with Tool Call Inspection
python chat.py --provider openrouter --version v3

4. Lab Rubric & Scoring Map

  • Prompt & Tool Descriptions (20 pts): Accurate descriptions in tools.yaml matching registry; clear rules in system_prompt.md.
  • Iterative Evidence v0 → v3 (20 pts): Concrete hypotheses, clean runs with provider_error_cases == 0, logged in version_log.csv.
  • 10 Team Eval Cases (10 pts): 5 single-turn + 5 multi-turn in data/eval_group.json.
  • Conversation & Safety (15 pts): 12 adversarial cases, analyzing 3 in detail (no data leakage, no hallucinated IDs).
  • UI & Transcript (10 pts): Functional chat UI displaying tool calls, inputs, errors, and transcripts.
  • Report & Teamwork (15 pts): REPORT.md, TEAM.md, and individual reflections.
  • Technical Bonus (10 pts): 1 custom-built tool with schema, implementation, eval cases, and demo.
